# Contributing to Verse Visual Editor

Thank you for considering a contribution to Verse Visual Editor. Contributions
of all sizes can help make visual Verse authoring clearer, safer, and more
useful.

These guidelines are intended to make expectations clear and to respect the
time of contributors and maintainers.

## Ways to Contribute

Helpful contributions include:

- Reporting reproducible bugs.
- Suggesting focused improvements.
- Improving documentation and examples.
- Adding or improving tests.
- Fixing existing issues.
- Reviewing and testing proposed changes.

For substantial changes, please open an issue before beginning work. This lets
us agree on the problem and intended behavior before significant time is spent
on an implementation.

Please use issues for actionable bugs and proposals rather than general support
requests.

## Ground Rules

- Be respectful, patient, and welcoming.
- Keep each contribution focused on one problem or feature.
- Preserve existing Verse text and formatting unless the change intentionally
  edits that text.
- Include tests for behavior that reads, modifies, or writes Verse files.
- Do not include Epic Games source code or other material that cannot legally
  be redistributed with this plugin.
- Avoid unrelated cleanup in the same pull request.
- Explain user-visible changes clearly.

## Your First Contribution

The best place to start is to first **talk to a maintainer**! Let's see how the
work you'd like to do would fit and get everyone on the same page first. We
wouldn't want you to do a ton of work in the wrong direction. Open an issue and
start a discussion.

## Submitting a Change

1. Fork the repository and create a branch for one focused change.
2. Make the change in a game project using a compatible UE6-main checkout.
3. Add or update relevant tests and documentation.
4. Verify the affected behavior locally.
5. Open a pull request describing the problem, the proposed solution, and how
   you verified it.

Keep pull requests small enough to review. If a change naturally contains
several independent parts, submit them separately when practical.

By submitting a contribution, you confirm that you have the right to provide
it and agree that it may be distributed under the project’s license.

## Reporting a Bug

Search existing issues before opening a new report. Include:

- The UE6-main revision or date you are using.
- Your operating system.
- The Verse Visual Editor version or commit.
- A minimal Verse example that reproduces the problem, when possible.
- Clear steps to reproduce the behavior.
- What you expected to happen.
- What actually happened.
- Relevant screenshots, messages, or logs with sensitive information removed.
